# Review task to fix

Цель - исправить обоснованные замечания ревьюверов, но не выполнять все комментарии без проверки

## Порядок работы

1. Найди MR текущей ветки. Для работы с GitLab можешь использовать установленный `glab`. Если MR не найден, сообщи об этом
2. Получи все обсуждения MR, включая закрытые. Основное внимание уделяй незакрытым обсуждениям
3. Для каждого замечания изучи всю ветку обсуждения, связанный код и актуальное состояние файлов. Учитывай, что замечание могло быть уже исправлено или относиться к устаревшему коду
4. Самостоятельно исправляй однозначные замечания, если решение не требует изменения бизнес-логики, API-контрактов или архитектуры
5. Спорные замечания не исправляй. Выноси их на решение пользователя с объяснением и возможными вариантами
6. После исправлений проверь изменения и запусти подходящие тесты, линтер и проверку типов
7. Не изменяй посторонний код и не перезаписывай существующие изменения пользователя

## Формат результата

- **Исправлено** - внесённые изменения с указанием файлов
- **Уже исправлено** - замечания, которые не потребовали изменений
- **Нужно решение** - спорные замечания с объяснением и вариантами решения
- **Проверки** - результаты выполненных проверок

Не добавляй пустые разделы и не повторяй одинаковые замечания

## Ограничения

- Не делай commit и push
- Не отвечай на комментарии и не закрывай обсуждения в GitLab
- Не исправляй замечания вслепую
- Не принимай спорные решения за пользователя
