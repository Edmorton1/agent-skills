# Task review

Цель - проверить реализацию задачи по реальным правилам команды до ревью в GitLab. Это не замена обычному поиску багов через `/review`

## Порядок работы

1. **Обязательно прочитай** файл `references/review-rules.md` внутри директории этого скилла. Если файл отсутствует или не читается, сообщи об этом и не выдавай обычное ревью за проверку по правилам команды
2. Определи изменения текущей задачи относительно целевой ветки MR. Если MR нет - используй основную ветку проекта. Учитывай коммиты текущей ветки, staged/unstaged изменения и новые файлы. Не включай чужие изменения и не меняй состояние Git
3. Прочитай изменённый код и необходимый соседний контекст. Для каждого **применимого** правила из `review-rules.md` проверь, соблюдено ли оно. При необходимости сравни с аналогичными реализациями в проекте
4. Сообщай только о конкретных нарушениях или хорошо обоснованных рисках. Не придирайся к коду, который соответствует правилам. Не предлагай субъективный рефакторинг без причины. Если правило не подходит к изменениям, пропусти его
5. Перед отчётом перепроверь каждое замечание: оно должно относиться к текущим изменениям, иметь точное место в коде и понятный способ исправления

## Формат результата

Для каждого замечания укажи:
- Приоритет: `high`, `medium` или `low`
- `путь/к/файлу:строка`
- Какое правило нарушено
- Почему это проблема и что нужно исправить

Сначала покажи важные замечания. Не повторяй одинаковые проблемы. Если нарушений нет, так и напиши

Если требования задачи или база сравнения недоступны, коротко укажи ограничение проверки

## Ограничения

- Не изменяй файлы, не создавай коммиты и не делай push
- Не публикуй комментарии и не меняй статусы обсуждений в GitLab
- Не выдумывай правила и не объявляй личные предпочтения обязательными требованиями
