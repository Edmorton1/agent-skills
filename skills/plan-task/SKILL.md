# Планирование задачи

Карта репозиториев: `/home/user/deploy/env/development/services/md`

Цель - изучить текущую реализацию и составить технический план с минимальными необходимыми изменениями

## Правила

- Не изменяй код и не начинай реализацию
- Не считай мои предположения и предложенные решения заведомо правильными
- Используй существующую архитектуру, компоненты и паттерны
- Избегай лишних абстракций, зависимостей и несвязанного рефакторинга
- Не принимай важные архитектурные решения без моего согласования
- Разделяй подтверждённые факты и предположения, неизвестное уточняй
- Исследуй только релевантный код, не трать контекст на изучение всего проекта
- Пиши кратко и конкретно, ссылайся на файлы при описании существующей реализации

## Задача

1. Изучи согласованные требования из предыдущего анализа
2. Определи связанные репозитории по карте, документации и структуре проекта
3. Найди текущую реализацию, похожие решения и доступные для переиспользования компоненты
4. Изучи зависимости между сервисами и существующие API-контракты
5. Определи необходимые изменения по каждому репозиторию
6. Предложи технические решения
7. Проверь корректность типов данных, сериализации и контрактов между сервисами
8. Определи зависимости между изменениями, порядок реализации и релизов
9. Предусмотри необходимые миграции, проверки
10. Убедись, что план покрывает все согласованные требования
11. Выяви технические риски и вопросы, влияющие на реализацию

## Исследование кода

- Начинай с дешёвого поиска, углубляйся только при необходимости
- Не сканируй все репозитории и не читай большие файлы целиком без причины
- Ищи существующие решения также в репозиториях, которые не планируется изменять
- Прекращай исследование, когда информации достаточно для обоснованного плана
- Если что-то не удалось проверить, явно укажи это

## Результат

Представь:

1. **Текущее состояние** - затронутые репозитории, существующая реализация и переиспользуемые решения
2. **План реализации** - конкретные изменения по репозиториям с указанием файлов и компонентов
3. **Контракты и зависимости** - изменения API, типов данных и порядок реализации/релизов
5. **Риски и вопросы** - технические ограничения, неопределённости и решения на согласование

Не создавай пустые разделы

После составления плана остановись и дождись моего согласования
